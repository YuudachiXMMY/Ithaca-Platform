### Q12 evidence — the Chinese copy is human-authored

Assessed 2026-09-29 by sampling 25 values across prefix families. `messages/en.json` and
`messages/zh.json` each hold 710 message keys with exact parity.

- **Sentence structure is rebuilt across key boundaries.** `programs_eliteInterview_faq_reachUsPrefix` / `_reachUsSuffix` render as `prefix + email + suffix`. EN: `Reach us at` / `if you need more information.` ZH moves the entire conditional clause into the prefix (`如需更多信息，请联系`) and reduces the suffix to `。`. This requires knowing how the two keys are concatenated at render time — machine translation cannot do it.
- **Non-literal idiom**: `skills they carry for life` → `锻造成陪伴一生的能力`; `why … are essential` → `何以不可或缺`; `coincides with` → `不期而遇`.
- **The Chinese sometimes says more than the English** (`home_highlights_item4Description` appends `激发集体智慧`, with no EN source).
- **CJK typographic convention applied**: corner brackets 「」 rather than copied EN quotes; consistent spacing around Latin runs.
- **Locale-appropriate reformatting**: `10:00 AM - 12:00 PM` → `上午 10:00 - 中午 12:00` (chooses 中午 for noon, where MT typically emits 下午 12:00).
- **The translator corrected source-side errors**: the EN typos `withthe` and `Grand Prize..` in `programs_aiCamp_overview_p2` are fixed in the Chinese.

**Consequence**: the Chinese workstream is "author copy for the new pages + fix the specific
defects listed in `CONTENT-GAPS.md` + CJK typography acceptance", not a full rewrite.

## Open / deferred

### 🟠 The Chinese webfont is ON; `/zh` carries a documented +1.28s for it

**Resolves the former 🔴 "the self-hosted Chinese face has been inert in production"**, per owner
ruling D-8. The defect: the font stack composed to `Inter, sans-serif, 'Noto Sans SC', …` — **a
generic family second**, inherited from the pre-D6 `--font-outfit: 'Outfit', sans-serif`. CSS font
matching stops at a generic, so the browser never reached Noto Sans SC; `/zh` fetched the stylesheet
and **zero of the 505 subset files**, and Chinese rendered in PingFang from the day the CJK work
shipped. `--font-cjk-deferred` is deleted and `src/lib/font-stack.test.ts` asserts the ordering
property directly, so it cannot come back.

**What made it affordable.** Fontsource's stock output is ~101 generic `unicode-range` subsets × 5
weights — 505 committed binaries, 13 MB in git, 1.6 MB fetched per `/zh` view. That partitioning
exists for sites whose text is unknown at request time. This site's is not: every public page is
prerendered, so the renderable character set is finite. `scripts/build-cjk-subset.ts` computes it at
build time — **935 codepoints, 901 of them Han** — and cuts Noto Sans SC to exactly that. The 505
binaries are deleted; the output is generated and gitignored, so it cannot drift from `messages/`.

Four further decisions, each measured rather than assumed:

| decision                                 | why                                                                                                                                                                                                                                                                                      |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **2 weights (400/700)**, not 5, not 3    | Every weight is fetched — there is no `unicode-range` left to skip any — so a third weight was 122 KB competing with the LCP element. Chinese typography does not lean on light weights the way Latin does.                                                                              |
| **No `unicode-range`**                   | One file per weight holding exactly this site's glyphs; English pages never load the stylesheet. Spelling out 901 Han codepoints three times cost ~18 KB of render-blocking CSS to buy nothing. The stylesheet is now **1.1 KB**.                                                        |
| **`font-display: optional`**, not `swap` | Under `swap` the text repaints when the font lands and Chrome re-records LCP at the repaint — LCP became "when did the font arrive" regardless of file size.                                                                                                                             |
| **Not preloaded**                        | `/zh`'s LCP element is the header logo, which already carries `fetchpriority="high"`. A preloaded font sits at the same priority and takes bandwidth from it; removing the preload moved `/zh` 6.24s → 5.65s and brought `/zh/programs/ev-challenge` back under its own ceiling unaided. |

**Measured** — same harness, mobile `lighthouserc` profile, median of 3:

| `/zh` LCP                                              |             |
| ------------------------------------------------------ | ----------- |
| CJK off (what shipped for months)                      | 4.37 s      |
| naive fix: stock 505 subsets, 5 weights                | 11.58 s     |
| subset, 3 weights, 373 KB, `swap`, preloaded           | 6.62–6.99 s |
| **shipped: 2 weights, 251 KB, `optional`, no preload** | **5.65 s**  |

**505 files / 1655.8 KB → 2 files / 251.1 KB.** CLS held at 0.000 on every route throughout.

So **having the Chinese typeface costs +1.28 s on `/zh`**, and that remainder is irreducible: 900 Han
glyphs is ~125 KB per weight. `lighthouserc.json` ratchets the zh routes at **5800 ms** — at the
measured value, not with headroom, so the page cannot get slower without failing.

Verified in a browser rather than inferred: both faces fetched, `document.fonts.check()` true for
Han, and `Noto Sans SC` in the h1 chain with no generic in front of it.

**The next lever, if the owner wants the gate back at 4500:** defer the stylesheet past the `load`
event. Measured at **5.12 s**, but it means the font never applies on a first view at all — only
from cache on the second page. Worth taking only if `/zh` LCP matters more than a first-time
visitor seeing the typeface. The other lever is the logo: it is `/zh`'s LCP element, and nothing has
been done to it.

### Header chrome: one ground signal, and a scrim to make it true

**Reported as** "the top menu's text is hard to see on home / about-us / EV / Ithaca Dialogues /
Engineering Projects / Summer & Winter Camps; some pages may need `logo-ink.png`".

**Measured before the change**, by sampling the actual rendered pixels behind every piece of header
chrome on all 28 sitemap routes at desktop and mobile: **40 of 84 elements below 4.5:1**, the worst
at **1.01:1** — not "hard to read", invisible.

| route                                                                            | nav links, unscrolled | mobile hamburger |
| -------------------------------------------------------------------------------- | --------------------- | ---------------- |
| `/`, `/about-us`                                                                 | 1.0–1.7               | 1.16–1.57        |
| `/programs/{ev-challenge,engineering-projects,summer-winter-camps,ithaca-night}` | **1.01**–1.88         | 1.26–1.88        |
| `/programs/{ithaca-dialogues,ai-entrepreneurship-bootcamp}` (split heroes)       | 1.62–3.57             | 1.42             |
| `/programs`, `/admissions`, `/results`, `/contact-us`, `/privacy`, `/terms`      | 7.4–8.9 ✓             | 9.3 ✓            |

**Root cause.** The ground was decided _twice_. `Header.svelte` had a path test that chose between
`logo.png` and `logo-ink.png`; the nav links, the hamburger and the language switcher had no test at
all and kept the §8.2 light palette's ink tokens on every route. The logo was right and everything
beside it was wrong, which is why the report reads as two separate problems.

| decision                                                           | why                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **One predicate**, `headerOnDark()` in `$lib/data/nav`             | The wordmark and the links can no longer be told different things about the same background. The logo swap is now a _consequence_ of the ground, not a parallel opinion about it.                                                                                                                                                                        |
| **Dark state uses the existing `band-*` scale**, not ad-hoc whites | `app.css` already publishes `band-foreground-muted` at 10.37:1 and `band-brand` at 7.94:1 _on navy-900_. Reusing them means the header inherits numbers that were already argued for.                                                                                                                                                                    |
| **A gradient scrim under the transparent header**                  | Without it, "white text on a dark hero" is a hope, not a property. The EV Challenge photo has a bright green patch that leaves even **pure white at 3.2:1**, and the two split heroes put a white panel under half the bar. The scrim makes the ground a known quantity across the full width, so a future hero photo cannot quietly break the contract. |
| **Scrolled bar 70% → 90% opaque**                                  | At 70% the bar's contrast still depended on the page content scrolling under it: the hamburger measured **4.29:1** on `/`. This was pre-existing and nothing had ever looked at it.                                                                                                                                                                      |

**Split heroes — provisional.** `/programs/ithaca-dialogues` and `/programs/ai-entrepreneurship-bootcamp`
put a photo under one half of the bar and a white panel under the other, so no single text colour
works. The owner chose the full-width scrim for consistency with the other six dark pages, knowing
it washes the white half (2026-10-01: _"先尝试使用这个方案，后续如果效果不佳再尝试其他方案"_). **If it reads
badly, the fallback is to drop those two routes out of `headerOnDark()` and let them use the solid
scrolled-style bar instead** — the predicate is one function and the contrast spec will confirm the
result either way.

**Why nothing caught this.** `a11y.spec.ts` runs axe on every page in both locales and was green
throughout. axe reports text-over-image contrast as **incomplete**, never as a violation, so it is
structurally blind to this entire defect class. `e2e/header-contrast.spec.ts` now samples the real
pixels — hiding the header's _content_ while keeping its _decoration_, since the scrim and the
scrolled background are painted by the header itself and are part of the ground.

**One more, found in review.** `headerOnDark` is a path prefix, so an unmatched
`/programs/<typo>` — a stale WeChat share, a bookmark, a slug renamed later — satisfied it while
rendering `+error.svelte`, which is a plain **white** page. The old code got this subtly wrong (the
white wordmark on white); the scrim made it conspicuous, painting a navy band across the 404. Fixed
by keying on `page.status < 400` rather than by allowlisting slugs, which covers every error page at
once including routes that do not exist yet. The sitemap cannot list a 404, so the sweep above was
structurally blind to it and the spec now checks that route by name.

**After:** 0 of 84 below 4.5:1, both viewports, unscrolled and scrolled. `lhci` still exits 0.

| #   | Decision                                                                                            | Reasoning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L-1 | The locale switch moved from the header bar to the **first footer column**, and `lg` stayed         | Re-measured in Chrome at the real type scale: a 104px logo in a `1fr auto 1fr` grid inside `max-w-[1400px] px-12` leaves **412px** per side at 1024px. | L-2 | `LocaleSuggestion.svelte` replaces the discoverability the header switch gave up                    | The PRD's central hypothesis is that a native-language path converts Chinese-speaking parents, and a switch below the fold is a real regression against it. It must be client-only (every public page is prerendered, so there is no `Accept-Language` to read) and `position: fixed` (the Lighthouse gate is CLS ≤ 0.05). | L-4 | Success Stories sits at `/success-stories`, not under `/student-life`                               | Owner's call, and the right one: it is the only page in that group with real content and real search value, and three segments under a stub is a worse URL than a flat one. `checkActive` in `Header.svelte` was generalised to mark a group active when any CHILD matches, so the bar is not left blank on that page.                                                                                                                                                                                                                                                                               |

That state passes `header-contrast` (same colours, same ground), passes axe, and screenshots cleanly. The spec measures the bar at 1600px, where it certainly fits, and requires the same height at 1024 and 1280 — self-calibrating, so it survives a type-scale change.                                                                                                                                                       |
| L-8 | `nav.test.ts` now derives nav hrefs from the route glob                                             | Seven destinations were added at once. A single typo (`/academics/osssd`) would have shipped a header link to a 404 — and `headerOnDark` claims that subtree by prefix, so the white error page would also have had an invisible nav.
